۱) معرفی و معماری سامانه

فرایارا یک سامانه تحت وب برای طراحی، ثبت، نسخه‌بندی، استفاده و گزارش‌گیری از فرایندها، فرم‌ها، داده‌ها، آزمون‌های مشاوره و الگوهای قرارداد است. هدف اصلی این است که اطلاعات سازمان به‌جای فایل‌های پراکنده، به‌صورت منابع شناسه‌دار (کد نمایشی + UUID)، نسخه‌دار، دارای مالک و وضعیت نگهداری شوند.

هشت زیرسیستم مطابق سند: مدیریت کاربران و دسترسی، مدیریت فرایندها، مدیریت فرم‌ها، کاتالوگ داده، مدیریت آزمون‌ها، مدیریت قراردادها، گزارش‌ها و داشبوردها، مدیریت اسناد و ممیزی.

معماری (Modular Monolith)

React (RTL فارسی)
   │  HTTPS / REST API  (/api/v1)
   ▼
FastAPI
   ├── Authentication & Authorization  (JWT + Argon2 + RBAC)
   ├── Workflow Engine        ← موتور اجرای محدود BPMN
   ├── Forms                  ← فرم‌ساز و ثبت پاسخ
   ├── Data Catalog           ← کاتالوگ مرکزی فیلدها
   ├── Assessments            ← بانک آزمون + نمره‌گذاری امن
   ├── Contracts              ← الگو و تولید قرارداد
   ├── Reporting              ← داشبوردها و خروجی‌ها
   └── Audit & Files          ← ممیزی، فایل، پشتیبان‌گیری
   │
   ├── SQLite (WAL + foreign_keys)
   └── Private File Storage / Background Jobs

اصل جداسازی طراحی از اجرا (بخش ۱ سند)

طراحی نمودار BPMN با اجرای واقعی آن متفاوت است. در این پیاده‌سازی، ویرایشگر bpmn-js پشتیبانی کامل مدل‌سازی را دارد، اما موتور اجرایی نسخه نخست فقط این عناصر را واقعاً اجرا می‌کند:

قابل اجرا (دامنه موتور نسخه نخست)فقط قابل طراحی (خارج از دامنه اجرا)
رویداد شروع/پایان ساده، User Task، مسیر ترتیبی، Exclusive Gateway با شرط روی داده‌های فرم Parallel / Inclusive / Event-Based Gateway، Timer، Service/Script/Manual Task، Subprocess، Call Activity، پیام‌ها، Boundary Event و…
اگر نموداری شامل عناصر خارج از دامنه اجرا باشد، در زمان «انتشار اجرایی» با پیام روشن مسدود می‌شود (ماتریس پشتیبانی BPMN — بخش ۴.۲ سند). عناصر طراحی می‌شوند ولی اجرای خودکار نمی‌گیرند.

۳) نصب و راه‌اندازی بک‌اند

1
ورود به پوشه بک‌اند و ساخت محیط مجازی: 
cd Farayara/backend
python3 -m venv .venv
# لینوکس/مک:
source .venv/bin/activate
# ویندوز:
.venv\Scripts\activate
2
نصب وابستگی‌ها: 
pip install -r requirements.txt
شامل: FastAPI، Uvicorn، SQLAlchemy، Pydantic v2، PyJWT، Argon2-cffi، Openpyxl، bleach، Alembic، pytest و…
3
داده اولیه (Seed) — خودکار: 
uvicorn app.main:app --reload --port 8000

از این نسخه، در اولین راه‌اندازی سرور داده اولیه به‌صورت خودکار بارگذاری می‌شود و نیازی به دستور جداگانه نیست. در صورت تمایل به بارگذاری/بازنشانی دستی، همچنان python -m app.seed در دسترس است (اجرای تکراری آن بی‌خطر است و داده را دوباره نمی‌سازد). این دستور پایگاه داده backend/data/farayara.db را می‌سازد و شامل: سازمان نمونه، ۲۶ مجوز، ۱۱ نقش سند، ۹ کاربر نمونه، ۱۱ فیلد مرجع کاتالوگ، یک فرم منتشرشده «درخواست خدمات»، یک فرایند منتشرشده با Gateway شرطی، یک آزمون نمونه دارای مجوز داخلی با قواعد و مثال‌های مرجع، و یک الگوی قرارداد منتشرشده است. اجرای دوباره seed تکرار نمی‌شود (ایمن).

4
اجرای سرور: 
uvicorn app.main:app --reload --port 8000
  • سامانه (API): http://localhost:8000
  • مستندات تعاملی Swagger: http://localhost:8000/api/docs
5
(اختیاری) مهاجرت‌های Alembic: 
# اعمال مهاجرت‌ها روی یک دیتابیس تازه:
alembic upgrade head
# پس از تغییر مدل‌ها، تولید مهاجرت جدید:
alembic revision --autogenerate -m "describe change"
alembic upgrade head
6
(اختیاری) اجرای تست‌ها: 
python -m pytest tests/ -v
۳۲ تست شامل معیارهای پذیرش سند: AC-01 تا AC-16.

مجوزهای مستقل حساس (بخش ۳.۲ سند)

  • طراحی فرم (form.create) از مشاهده پاسخ‌ها (form.submissions.view) جداست.
  • مشاهده نتایج روان‌شناختی مجوز مستقل assessment.result.view می‌خواهد.
  • خروجی گرفتن داده‌ها (export.data) و دریافت فایل (file.download) مجوز جداگانه دارد.
  • کنترل دسترسی در بک‌اند انجام می‌شود؛ مخفی‌شدن دکمه در فرانت کافی نیست (تست AC-16).

۶) داشبورد مدیریتی

صفحه نخست پس از ورود؛ شاخص‌های عمومی با تعریف محاسباتی روشن (بخش ۱۳.۱ سند):

  • کارت‌های آماری: فرایندها (به‌همراه تعداد نسخه منتشرشده)، فرم‌ها، فیلدهای فعال کاتالوگ، پاسخ‌های نهایی ثبت‌شده، اجرای آزمون‌ها، قراردادهای تولیدشده، وظایف باز کل سامانه و وظایف باز شما.
  • روند پاسخ‌های ۱۴ روز اخیر: نمودار میله‌ای تعداد پاسخ‌های ثبت‌شده به تفکیک روز.
  • وضعیت نسخه‌های فرایند: سهم پیش‌نویس/منتشرشده/بازنشسته.
  • پراستفاده‌ترین فیلدها: بر اساس تعریف داشبورد اصلی سند — «تعداد فرم‌های منطقی متمایزی که از فیلد استفاده می‌کنند».
برای جداسازی مفاهیم، «تعداد فرم» همیشه یعنی تعداد فرم منطقی و «نسخه منتشرشده» جداگانه گزارش می‌شود (الزام بخش ۱۳ سند).

۷) کاتالوگ داده (فیلدهای مرجع)

هسته استانداردسازی اطلاعات سازمان (بخش ۷ سند). برای مثال «شماره موبایل» یک فیلد مرجع است که می‌تواند در ده فرم با عنوان نمایشی متفاوت استفاده شود — بدون آنکه هویت فیلد عوض شود.

ایجاد فیلد مرجع

1
به «کاتالوگ داده» بروید و روی «+ فیلد مرجع جدید» بزنید.
2
عنوان فارسی را بنویسید — سامانه بلافاصله فیلدهای مشابه را پیشنهاد می‌دهد (بدون ادغام خودکار، طبق بخش ۷.۳ سند). اگر فیلد مشابه وجود دارد، از همان استفاده کنید.
3
نام فنی لاتین (mobile_number)، نوع داده، دسته‌بندی، مترادف‌ها، سطح حساسیت (عادی/حساس/بسیار حساس)، پرچم‌های «هویتی» و «سلامت» و قواعد اعتبارسنجی JSON را تکمیل و ذخیره کنید.

فراوانی چندشاخصی (بخش ۷.۴ سند)

در صفحه جزئیات هر فیلد، شاخص‌های مستقل نمایش داده می‌شود:

شاخصتعریف
تعداد فرم‌های استفاده‌کنندهفرم‌های منطقی متمایز دارای فیلد (مبنای داشبورد اصلی)
تعداد نسخه‌های استفاده‌کنندهنسخه‌های فرم دارای فیلد
تعداد جایگاه‌هادفعات حضور فیلد در ساختار فرم‌ها
پاسخ ثبت‌شده / مقادیر غیرخالی / نرخ تکمیلبر اساس جدول مقادیر گزارش‌پذیر پاسخ‌ها
فراوانی مقادیرتوزیع پاسخ‌ها (مثلاً چند «بله» و چند «خیر»)

مسیر استفاده

صفحه جزئیات فیلد نشان می‌دهد «فیلد ← نسخه فرم» در کدام فرم‌ها با کدام عنوان و الزام استفاده شده است.

فیلد استفاده‌شده حذف فیزیکی نمی‌شود؛ فقط «غیرفعال‌سازی» می‌شود (حذف منطقی — بخش ۷.۳). تغییر نوع یا قواعد فیلد منتشرشده یک نسخه جدید فیلد می‌سازد.

۸) فرم‌ساز و ثبت پاسخ

ساخت فرم با کشیدن و رهاکردن

1
در صفحه «فرم‌ها» روی «+ فرم جدید» بزنید؛ مستقیماً به فرم‌ساز می‌روید.
2
از جعبه‌ابزار سمت راست، نوع فیلد را با ماوس بکشید و در «ساختار فرم» رها کنید. انواع پشتیبانی‌شده: متن کوتاه/بلند، عدد، مبلغ، درصد، تاریخ، انتخاب تکی/چندگانه، بله/خیر، ایمیل، تلفن، کد ملی (با بررسی checksum)، نشانی وب.
3
با کشیدن، ترتیب فیلدها را جابه‌جا کنید. روی هر فیلد کلیک کنید تا پنل مشخصات باز شود: عنوان نمایشی، کلید فنی، متن راهنما، الزامی بودن، گزینه‌ها، حداقل/حداکثر.
4
اتصال به کاتالوگ: با دکمه «اتصال به فیلد کاتالوگ» فیلد را به فیلد مرجع متصل کنید تا فراوانی استفاده آن قابل رصد باشد. اتصال، نوع و قواعد اعتبارسنجی را از کاتالوگ می‌گیرد.
5
با «پیش‌نمایش» شکل نهایی فرم را ببینید؛ با «ذخیره ساختار» ذخیره کنید؛ با «انتشار نسخه» فرم را برای پاسخ‌گیری منتشر کنید.

نسخه‌بندی فرم (AC-06)

  • نسخه منتشرشده تغییرناپذیر است؛ دکمه ویرایشگر روی نسخه منتشرشده غیرفعال است.
  • برای ویرایش، «ایجاد نسخه جدید برای ویرایش» را بزنید — نسخه پیش‌نویس جدید با همان ساختار ساخته می‌شود.
  • پاسخ‌های قبلی به نسخه خودشان متصل می‌مانند و هرگز تغییر نمی‌کنند.

تکمیل فرم و کد رهگیری

از فهرست فرم‌ها، روی فرم منتشرشده «تکمیل فرم» بزنید. اعتبارسنجی الزامی‌ها، قالب (pattern)، ایمیل و کد ملی (با الگوریتم checksum) سمت کلاینت و الزامی‌ها مجدداً سمت سرور انجام می‌شود. پس از ثبت نهایی، کد رهگیری (مانند TRK-00000042) نمایش داده می‌شود.

پاسخ‌های ثبت‌شده و خروجی‌ها

در صفحه پاسخ‌های هر فرم: مشاهده جزئیات هر پاسخ + خروجی CSV / Excel / JSON با محافظت در برابر فرمول‌تزریقی (پیشوند ' برای مقادیر خطرناک — بخش ۱۹ سند). خروجی CSV با BOM ذخیره می‌شود تا فارسی در Excel درست نمایش داده شود.

«خروجی تعریف فرم» (JSON قابل ورود مجدد) از دکمه‌ای در API: POST /forms/{id}/export — و «خروجی پاسخ‌ها» دو نوع جدا هستند (بخش ۶.۵ سند).

۹) طراحی و اجرای فرایند (BPMN)

ویرایشگر bpmn-js

1
در صفحه «فرایندها» یک فرایند بسازید و وارد «مدیریت» شوید — تب «نمودار BPMN» ویرایشگر کامل باز می‌شود.
2
از پالت سمت چپ، عناصر (رویداد شروع/پایان، وظیفه کاربر، Gateway، رویداد میانی، زیرفرایند، Pool/Lane و…) را بکشید و با فلش‌ها به هم متصل کنید. دابل‌کلیک برای تغییر نام.
3
اتصال فرم و نقش به گره‌ها: روی هر User Task کلیک کنید تا در پنل کناری، «فرم مرحله» (از نسخه‌های منتشرشده فرم) و «نقش مجری» یا «کاربر مجری مشخص» را تعیین کنید. روی یال‌های خروجی Gateway کلیک کنید و شرط مسیر را بنویسید (مثال: review_result == "yes").
4
«ذخیره نمودار» هم XML و هم تصویر SVG نسخه را ذخیره می‌کند. «اعتبارسنجی» خطاهای ساختاری و عناصر خارج از دامنه اجرا را گزارش می‌دهد (AC-01، AC-02).
5
«انتشار نسخه» (با مجوز process.publish) فقط برای نمودار معتبرِ فاقد عنصر خارج از دامنه اجرا ممکن است؛ در غیر این صورت پیام روشن می‌دهد.

اجرای فرایند

1
روی نسخه منتشرشده، «شروع اجرا» بزنید و متغیرهای اولیه JSON را وارد کنید (AC-03 — شروع فقط روی نسخه منتشرشده).
2
موتور اجرا به‌ترتیب پیش می‌رود؛ در هر User Task می‌ایستد و وظیفه در کارتابل نقش/کاربر مجری می‌نشیند و اعلان ثبت می‌شود.
3
در Gateway، شرط یال‌ها روی متغیرهای نمونه (داده‌های فرم مراحل قبلی) ارزیابی امن می‌شود؛ مسیر درست انتخاب و در تاریخچه ثبت می‌گردد.
4
در تب «اجراها»، کد پیگیری (INS-...)، وضعیت، وظایف و خط‌زمانی کامل رویدادها قابل مشاهده است. مدیر می‌تواند اجرای در حال رشد را لغو کند.
تضمین‌های اجرایی (بخش ۵.۳ سند): تکمیل تکراری یک وظیفه دو انتقال ایجاد نمی‌کند (AC-04)؛ تغییر وضعیت و ثبت داده در یک تراکنش انجام می‌شود؛ تمام تغییرات مسیر در ProcessEvent قابل ممیزی است؛ هر نمونه به نسخه ثابت فرایند متصل است.

فرایند نمونه seed

«فرایند بررسی و تأیید درخواست خدمات» با مسیر: ثبت درخواست → بررسی درخواست (فرم متصل، نقش کاربر اجرایی) → Gateway «نتیجه بررسی؟» → تأیید نهایی (نقش مدیر سازمان) یا اعلام رد → پایان. شرط‌ها: review_result == "yes" / review_result == "no".

۱۰) کارتابل من (وظایف)

وظایف در انتظار شما (بر اساس تخصیص مستقیم یا نقش) اینجا فهرست می‌شوند. با «انجام وظیفه» فرم مرحله باز می‌شود؛ پس از تکمیل، پاسخ به‌صورت خودکار در «پاسخ‌های ثبت‌شده» فرم مربوطه ثبت (با اتصال به نمونه و وظیفه) و فرایند به مرحله بعد می‌رود.

  • وظیفه تخصیص‌یافته به کاربر دیگر، برای شما قابل تکمیل نیست (خطای 403).
  • وظایف تکمیل‌شده با فیلتر «تکمیل‌شده» قابل مرور و مشاهده داده‌های ثبت‌شده‌اند.
  • اعلان وظیفه جدید در نوار بالای سامانه (دکمه «اعلان‌ها») نمایش داده می‌شود.

۱۱) آزمون‌های مشاوره

الف) بانک آزمون و شناسنامه (بخش ۹ سند)

هر آزمون شناسنامه کامل دارد: نام فارسی/اصلی/اختصاری، حوزه، مؤلف، ناشر/دارنده حقوق، وضعیت مجوز (دارای مجوز / مجوز خریداری‌شده / مالکیت عمومی / نامشخص / محدود)، جامعه هدف، تعداد سؤال، زمان، شیوه نمره‌گذاری، منابع علمی، هنجارها و محدودیت‌ها. هر نسخه آزمون مستقل است: سؤال‌ها، گزینه‌ها، سؤال‌های معکوس، سیاست پاسخ ناقص، قواعد محاسبه، هنجار و الگوی گزارش.

ب) جست‌وجوی اینترنتی آزمون‌ها (بخش ۱۰ سند)

1
دکمه «جست‌وجوی اینترنتی آزمون‌ها» → عبارت را وارد کنید. سامانه از منابع باز (ویکی‌پدیا فارسی + DuckDuckGo) نتایج متادیتا (عنوان، نشانی، خلاصه، تاریخ بازیابی) را می‌آورد.
2
«ورود به‌عنوان پیش‌نویس» یک آزمون draft با منبع و وضعیت «نامشخص» می‌سازد؛ اجرای رسمی ندارد تا مجوز بررسی و متخصص تأیید کند.
مرزهای قابلیت (بخش ۱۰.۲ سند): یافتن نام آزمون به معنی مجاز بودن ذخیره یا بازنشر سؤال‌ها نیست. سامانه پرداخت/ورود منابع را دور نمی‌زند، اطلاعات هویتی مراجع را به سرویس جست‌وجو نمی‌فرستد و ورود خودکار قواعد نمره‌گذاری بدون تأیید متخصص ممنوع است.

ج) سؤال‌ها و قواعد نمره‌گذاری

  • در تب «سؤال‌ها و قواعد»: افزودن سؤال، متن، کد، پرچم معکوس و گزینه‌ها با نمره.
  • مقیاس‌ها: هر مقیاس با فهرست سؤال‌ها یا عبارت محاسباتی امن (توابع مجاز sum، avg، min، max، round) محاسبه می‌شود؛ بازه‌های تفسیر (حداقل/حداکثر + برچسب + توضیح) تعریف می‌شوند.
  • سیاست پاسخ ناقص: نادیده‌گرفتن (skip) / نمره صفر / بی‌اعتبار کردن نتیجه + حداقل نسبت پاسخ برای اعتبار.
  • ممنوعیت eval (بخش ۱۱.۲): قواعد کاربر با ارزیاب امن AST اجرا می‌شود؛ دسترسی به فایل، شبکه، سیستم‌عامل و توابع ناشناس مسدود است و نسخه قواعد در هر محاسبه ثبت می‌شود.

د) اعتبارسنجی، تأیید و انتشار (بخش ۱۱.۳)

«اعتبارسنجی نمره‌گذاری» مثال‌های مرجع ثبت‌شده (Validation Cases) را اجرا و با خروجی مورد انتظار مقایسه می‌کند. انتشار نسخه نیازمند: ثبت تأیید علمی متخصص + وضعیت مجوز معتبر + داشتن سؤال و قواعد. (AC-10، AC-11)

هـ) اجرا و نتیجه (بخش ۱۱.۴)

1
«اجرای آزمون» → نام پاسخ‌دهنده → شروع پاسخ‌دهی → انتخاب گزینه‌ها → «ثبت پاسخ و محاسبه نمره».
2
صفحه نتیجه: نمره خام هر مقیاس، نمودار، تفسیر بر اساس بازه‌ها، نرخ کامل بودن پاسخ‌ها، هشدار اعتبار، متن گزارش و یادآوری «ابزار کمک به متخصص است، نه تشخیص قطعی».
3
«محاسبه مجدد» یک ScoreRun جدید با تصویر قواعد می‌سازد؛ نتایج تاریخی بی‌صدا تغییر نمی‌کنند (AC-13).
آزمون نمونه seed («پرسش‌نامه کوتاه رضایت شغلی — نمونه داخلی») محتوای ساخته‌شده داخلی با مجوز «owned» است تا چرخه کامل بدون مشکل حقوقی قابل آزمایش باشد.

۱۲) قراردادها

طراحی الگو (بخش ۱۲.۱)

1
«الگوهای قرارداد» → «+ الگوی جدید» → ویرایشگر غنی فارسی (Tiptap) باز می‌شود: بولد/کج، عناوین، فهرست، جدول.
2
در پنل «متغیرهای الگو»، متغیرها را با کلید نقطه‌ای تعریف کنید (مانند party_a.full_name، contract.amount) با نوع داده، پرچم الزامی و عنوان. سپس متغیر را از پنل «درج در متن» داخل متن بنشانید.
3
بندهای شرطی: با دکمه «بند شرطی» الگوی {'%{%if key%}متن مشروط{%endif%}'} درج می‌شود — اگر متغیر مقدار داشته باشد نمایش داده می‌شود.
4
«پیش‌نمایش» رندر با داده خالی را نشان می‌دهد (متغیرهای خالی نشان‌دار). «انتشار الگو» با مجوز تأیید حقوقی (contract.approve) و ثبت نام تأییدکننده انجام می‌شود.

تولید قرارداد (بخش ۱۲.۴)

1
«قراردادهای تولیدشده» → «+ تولید قرارداد از الگو» → انتخاب نسخه الگوی منتشرشده.
2
فرم متغیرها خودکار ساخته می‌شود؛ متغیر الزامی خالی، تولید نهایی را مسدود می‌کند (AC-14).
3
پس از تولید، متن و داده‌ها منجمد می‌شوند: ویرایش آینده الگو قرارداد قبلی را تغییر نمی‌دهد (AC-15). برای سند، هش SHA-256 ذخیره می‌شود که تشخیص تغییر فایل را ممکن می‌کند (توجه سند: هش به‌تنهایی امضای معتبر حقوقی نیست).
4
«دریافت سند» یک فایل HTML آماده چاپ (با سربرگ/پابرگ و هش) می‌دهد که از مرورگر قابل چاپ به PDF است. دریافت در ممیزی ثبت می‌شود.
اعتبار حقوقی متن قرارداد باید توسط مسئول حقوقی بررسی شود؛ اتصال به امضای الکترونیکی معتبر، الحاقیه، تمدید و یادآوری سررسید در قابلیت‌های توسعه‌ای فازهای بعد است (بخش ۱۲.۵ سند).

۱۳) کاربران، نقش‌ها و مجوزها

  • تب کاربران: ایجاد/ویرایش کاربر، تعیین نقش‌ها، فعال/غیرفعال‌سازی، تغییر رمز.
  • تب نقش‌ها و مجوزها: ماتریس کامل ۲۶ مجوز در گروه‌های «سیستم، دسترسی، گزارش، فرایند، فرم، کاتالوگ، آزمون، قرارداد» — نقش‌های سیستمی ۱۱گانه سند از قبل ساخته شده‌اند و می‌توانید نقش سفارشی بسازید.
  • مجوزها همیشه در بک‌اند کنترل می‌شوند؛ حتی اگر رابط را دور بزنید، API بدون مجوز پاسخ 403 می‌دهد.

۱۴) سوابق تغییرات (ممیزی)

رویدادهای ثبت‌شده مطابق بخش ۱۹ سند: ورود و تلاش ناموفق، ایجاد/ویرایش/انتشار منابع، ثبت پاسخ، خروجی داده، تولید و دریافت قرارداد، شروع/لغو اجرا، تکمیل وظیفه، تغییر قواعد آزمون، محاسبه مجدد نتیجه، تغییر تنظیمات و پشتیبان‌گیری.

  • فیلتر بر اساس کاربر، نوع رویداد و موجودیت + صفحه‌بندی.
  • لاگ ممیزی فقط افزودنی است و در اختیار کاربران عادی برای ویرایش نیست (مجوز audit.view).

۱۵) تنظیمات و پشتیبان‌گیری

  • تنظیمات: عنوان سامانه، حداکثر حجم آپلود، یکسان‌سازی ی/ي و ک/ك در جست‌وجو (کلید/مقدار قابل توسعه).
  • پشتیبان‌گیری: با دکمه «گرفتن نسخه پشتیبان»، دیتابیس با SQLite Backup API سازگار با WAL کپی و دانلود می‌شود (کپی ساده فایل در حین فعالیت روش اصلی نیست — بخش ۱۶ سند). نسخه پشتیبان باید شامل فایل‌های پیوست، تنظیمات و نسخه برنامه نیز در محل جداگانه نگهداری و دوره‌ای بازیابی آزمایش شود (بخش ۲۰ سند).
  • یادآوری‌های امنیتی استقرار عملیاتی در همین صفحه فهرست شده‌اند.

۱۶) سناریوهای عملی گام‌به‌گام

سناریو ۱ — از فیلد تا پاسخ و گزارش فراوانی

1
با steward در کاتالوگ، فیلد «شماره شناسنامه» بسازید (مترادف: شماره ثبت).
2
با fdesigner فرم جدید بسازید، فیلد را از جعبه‌ابزار بکشید و به فیلد کاتالوگ وصل کنید + چند فیلد دیگر.
3
انتشار نسخه → با operator دو سه پاسخ ثبت کنید → کد رهگیری بگیرید.
4
با steward جزئیات فیلد را باز کنید: فراوانی، نرخ تکمیل و مسیر استفاده به‌روز است. خروجی CSV پاسخ‌ها را بگیرید.

سناریو ۲ — طراحی و اجرای کامل یک فرایند

1
با pdesigner فرایند جدید بسازید و در ویرایشگر BPMN یک مسیر شامل دو User Task و یک Exclusive Gateway بکشید.
2
به هر User Task فرم منتشرشده و نقش بدهید؛ روی یال‌های Gateway شرط بگذارید؛ ذخیره و اعتبارسنجی کنید.
3
با admin انتشار دهید → با operator «شروع اجرا» → وظیفه در کارتابل ظاهر می‌شود.
4
وظیفه را با داده فرم تکمیل کنید → Gateway مسیر درست را برمی‌دارد → وظیفه دوم برای نقش بعدی → خاتمه → تاریخچه کامل در تب اجراها.

سناریو ۳ — چرخه کامل آزمون

1
با assessor آزمون «رضایت شغلی نمونه» را باز کنید؛ در تب سؤال‌ها «اعتبارسنجی نمره‌گذاری» را اجرا کنید — مثال‌های مرجع باید موفق باشند (مثلاً پاسخ کامل → نمره ۲۸).
2
«اجرای آزمون» → پاسخ‌دهی به ۶ سؤال (دو سؤال معکوس) → ثبت و مشاهده نمره، تفسیر و گزارش.
3
«محاسبه مجدد» را بزنید: ScoreRun دوم اضافه می‌شود و نتایج قبلی دست‌نخورده می‌ماند.

سناریو ۴ — تولید قرارداد

1
با contractx الگوی «قرارداد ارائه خدمات مشاوره» را باز کنید؛ متن و متغیرها را ویرایش و منتشر کنید.
2
«تولید قرارداد از الگو» → فرم متغیرها را پر کنید (اگر «نام طرف دوم» را خالی بگذارید تولید مسدود می‌شود — AC-14) → پیش‌نمایش → تولید.
3
الگو را تغییر دهید و دوباره وارد قرارداد شوید: سند قبلی تغییری نکرده است (AC-15). سند را دانلود و چاپ کنید.

نمونه‌های curl

# ورود و گرفتن توکن
TOKEN=$(curl -s -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"Admin@1234"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

# داشبورد
curl -s http://localhost:8000/api/v1/dashboards/overview -H "Authorization: Bearer $TOKEN"

# ایجاد فیلد مرجع
curl -s -X POST http://localhost:8000/api/v1/catalog/fields \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"tech_name":"postal_code","title_fa":"کد پستی","data_type":"text","validation_rules":{"pattern":"^[0-9]{10}$"}}'

# ثبت پاسخ فرم
curl -s -X POST http://localhost:8000/api/v1/form-versions/VERSION_ID/submissions \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"data":{"full_name":"علی رضایی","mobile_number":"09121234567"}}'

۱۸) امنیت و استقرار عملیاتی

الزامات پیش از بهره‌برداری واقعی (بخش ۱۹ سند)

  • HTTPS: با Nginx یا Caddy فعال شود. نمونه پیکربندی Nginx:
server {
    listen 443 ssl;
    server_name farayara.example.ir;
    # ssl_certificate ...; ssl_certificate_key ...;
    client_max_body_size 25m;

    location /api/ { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host; }
    location /     { root /var/www/farayara/dist; try_files $uri /index.html; }
}
# محدودیت تلاش ورود (نمونه):
# limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;
  • کلید امضا: export FARAYARA_SECRET_KEY="$(python3 -c 'import secrets;print(secrets.token_hex(32))')"
  • رمز عبور با Argon2 هش می‌شود؛ توکن‌ها انقضا و refresh دارند.
  • خروجی HTML قرارداد با bleach پاکسازی می‌شود؛ خروجی CSV/Excel در برابر فرمول‌تزریقی محافظت می‌شود؛ قواعد آزمون با ارزیاب امن اجرا می‌شود؛ پارس XML در برابر خطرات رایج مقاوم است.
  • SQLite معمولی رمزگذاری داخلی ندارد؛ برای داده‌های حساس، رمزگذاری دیسک/فایل و مدیریت کلید مستقل به‌صورت صریح انتخاب شود.
  • نسخه پشتیبان رمزگذاری و در محل جداگانه نگهداری و بازیابی آن دوره‌ای آزمایش شود (RPO/RTO با کارفرما تعیین شود).

۱۹) عیب‌یابی (FAQ)

مشکلراه‌حل
صفحه ورود باز می‌شود ولی «خطای شبکه» می‌دهد بک‌اند روشن نیست: uvicorn app.main:app --port 8000 را اجرا کنید؛ پورت‌های 8000 و 5173 آزاد باشند.
پس از ری‌استارت سرور، همه یک‌باره لاگ‌اوت شدند FARAYARA_SECRET_KEY تنظیم نشده و کلید تصادفی عوض شده است — متغیر محیطی را ثابت تنظیم کنید.
خطای database is locked SQLite با busy_timeout=5000 و WAL پیکربندی شده؛ بار نوشتن هم‌زمان سنگین را کاهش دهید (بخش ۱۶ سند) و تراکنش‌ها کوتاه بمانند. برای بار بالا مسیر ارتقا به PostgreSQL پیش‌بینی شده است.
seed اجرا نمی‌شود / پیام «قبلاً بارگذاری شده» برای شروع مجدد: سرور متوقف → حذف پوشه backend/data → دوباره python -m app.seed (داده‌ها پاک می‌شوند!).
انتشار فرایند خطای «عناصر خارج از دامنه اجرا» می‌دهد طبق طراحی سند درست است؛ عنصر غیرقابل اجرا (مثلاً Parallel Gateway) را حذف یا با User Task/Gateway جایگزین کنید.
نمودار BPMN بعد از ذخیره خالی است پیش از خروج از صفحه، «ذخیره نمودار» را بزنید (ذخیره خودکار نمودار در نسخه نخست وجود ندارد).
متن فارسی CSV در Excel به‌هم‌ریخته است فایل با BOM تولید می‌شود؛ اگر نسخه قدیمی Excel مشکل داشت، از خروجی Excel (xlsx) استفاده کنید.
جست‌وجوی اینترنتی آزمون نتیجه نمی‌دهد دسترسی شبکه سرور به منابع باز را بررسی کنید؛ خطاهای منبع در پاسخ API گزارش می‌شوند. این قابلیت به شبکه اینترنتی سرور وابسته است.
403 Forbidden در APIها کاربر جاری مجوز لازم را ندارد؛ با مدیر سامانه بررسی کنید (ماتریس مجوزها در صفحه نقش‌ها).

۲۰) محدودیت‌های شناخته‌شده و نقشه راه

محدودیت‌های نسخه نخست (شفاف، مطابق الزام «فهرست محدودیت‌ها» در بخش ۲۳ سند)

  • موتور اجرای BPMN محدود به دامنه بخش ۵.۲ سند است؛ عناصر دیگر فقط قابل طراحی‌اند.
  • خروجی PDF/DOCX فارسی به‌صورت مستقیم تولید نمی‌شود؛ سند قرارداد HTML آماده چاپ است (فاز سه سند).
  • صف پس‌زمینه پایدار (Background Jobs) به‌صورت جدول ردیابی پیاده شده؛ OCR و تولید سنگین PDF به فاز پنج موکول است.
  • امضای ترسیمی در فرم‌ها معادل امضای الکترونیکی معتبر حقوقی نیست؛ اتصال به سرویس امضا پروژه جداگانه است.
  • استقرار چندسازمانی عمومی هدف نسخه نخست نیست؛ ساختار داده organization_id را از ابتدا دارد.
  • جست‌وجوی اینترنتی آزمون‌ها به دسترسی اینترنت سرور وابسته و فقط متادیتا است.
